# 上手：从零到线上

这一篇写给**要写东西的人**，不假设你懂 Markdown、Git 或命令行。跟着走一遍，
你会有一个能发出去的站点，并且知道每一步在磁盘上留下了什么。

想找参考手册而不是教程：配置字段看 [配置说明](configuration.md)，
模板变量看 [统一模板](templates.md)，命令行参数看 [命令行工具](cli.md)。
零碎疑问直接翻 [常见问题](faq.md)。

## 先明确一件事：站点就是一个文件夹

StaticSmith 不用数据库、不需要账号，也不联网存你的东西。一个站点就是磁盘上的一个文件夹：

```
my-site/
├── staticsmith.toml   # 这个站点的设置（标题、地址、发布方式……）
├── content/           # 你写的文章，一篇一个 .md 文件
├── templates/         # 页面长什么样
├── themes/            # 配套的 CSS 等资源
└── dist/              # 「生成」之后出现：可以直接上传的静态网站
```

推论有三条，早知道省事：

- **备份 = 复制这个文件夹**（或者把它放进 Git，推荐但不强制）。
- 你可以用任何编辑器改 `content/` 里的文件，界面会发现改动并提示刷新。
- `dist/` 是产物，可以随时删掉重新生成，不用备份。

## 第一步：新建站点

打开应用，起始页点「新建站点」，选一套**版式**，再**选一个空目录**。目录名会被当成
站点标题，之后能在「设置 → 站点信息」里改。

版式有两套，选哪套只影响模板与样式，写出来的文件路径完全一样：

- **极简文档站**：橙色、单栏、适合文档与说明
- **博客园风格博客**：双栏带侧栏（分类、最新随笔、标签云），适合个人博客

已经打开着一个站点时，从菜单「站点 → 新建站点…」——会弹一层表单，字段和起始页那张
卡片一模一样。版式事后换代价不小（一套是十来个模板文件），所以两个入口都让你先选。


按下确定的一瞬间，上面那几个文件夹就被写好了，还带一篇示例文章——
所以你打开界面就能看到东西，而不是一片空白。


已经有站点的话点「打开站点」，选那个含 `staticsmith.toml` 的文件夹。
选错目录会直接告诉你「这里没有 staticsmith.toml」，不会默默建一个。

## 第二步：写第一篇

界面停在「内容」页，中间是空的编辑区，那里列着三步（写第一篇 → 生成一次 → 发布出去），
点第一步就是新建。也可以用左边列表标题行的「新建」，或菜单「编辑 → 新建文章…」。

填个标题、选个栏目（默认 `posts`），点「创建草稿」。左边列表里立刻出现这一篇，
中间开始能打字，右边是它最终的样子。

**关于开头那几行 `+++`：** 每篇文章顶部有一小段设置（标题、日期、标签、是不是草稿），
写成 TOML 格式。不想手写就点工具条右边的「属性」，用表单填——两边改的是同一份东西。

**觉得面板太多？** 菜单「视图 → 专注写作模式」把列表、预览、属性面板一起收起来，
只留编辑器与工具条，宽度全给正文。想回来就切「标准模式」。模式只改布局：
菜单、快捷键、命令面板一件不少。


写完按 `Ctrl+S` 保存。状态栏会说「已保存，待生成 N 个页面」——这个 N 是「有几个页面
受这次改动影响」，比如你改了标签，标签页也得跟着重做。

## 第三步：看效果

右边的预览是实时的，但它取不到图片与 CSS（技术原因：它在一个没有文件访问权限的
沙盒里）。想看真正的样子，用「工具 → 启动本地预览服务器」，它只监听你这台机器，
不会被别人访问到。

插图片最省事的办法是**直接粘贴或拖进编辑器**：文件会被复制到站点的资源目录里，
按内容命名（同一张图粘两次只存一份），地址自动插到光标处。

## 第四步：生成

按 `Ctrl+Enter`（或顶栏「生成」）。这一步把 `content/` 与 `templates/` 渲染成
`dist/` 里的一堆 `.html`。状态栏的「待生成 N / M」归零就是做完了。

默认是**增量**的：只重做受影响的页面，所以平时按一下很快。换了主题或改了全局模板
之后可以用「站点 → 完整重建」。

不想每次手动按：菜单「工具 → 保存后自动生成」勾上。

## 第五步：发布

「发布」页选一种方式：

- **Git**：把 `dist/` 推到一个仓库（GitHub Pages、Cloudflare Pages 这类）。
- **FTP**：传到自己的虚拟主机。注意 FTP 是**明文**协议，密码与内容都明文过网；
  在公共 Wi-Fi 这类不受信网络上请改用 Git。SFTP 暂不支持。

密码与 Token **不写进配置文件**，而是存进操作系统自带的凭据管理器
（Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service）。这样把站点文件夹
分享给别人、或提交进 Git，都不会连着密码一起泄露。

先点「检查连接与凭证」，通过了再「一键发布」。发布只上传变化的文件。

## 上线之前值得跑一遍

「体检」页有三项，都是把「读者会遇到的问题」列成清单：

- **SEO**：缺标题、缺描述、描述太长、几篇撞了同一个标题。
- **站内死链**：点了会 404 的链接（要先生成过，它读的是产物）。
- **媒体资源**：没人引用的图片（占地方）、引用了却不存在的图片（显示成裂图）。

每条都能点回那篇文章去改。要成批补的话，左边列表的「只看」下拉里有「待补 SEO」，
筛出来一次改完。

## 之后你可能想做的事

- **整理结构**：新建栏目、改栏目名。改名默认「保留旧地址」，老链接不会因为你整理
  一次目录就全断掉。
- **换外观**：「外观」页能看模板之间的继承关系、直接改共享组件，也能装别人做好的
  主题包（先列清单再决定是否覆盖）。
- **搬旧站过来**：「设置 → 导入内容」支持 Hugo / Jekyll 的 Markdown，强制「先扫后导」，
  确认清单再落盘，且绝不覆盖已存在的文件。
- **让 AI 帮忙**：「设置 → AI 接入」开一个只监听本机的端点，Claude、Cursor 这类助手
  就能读你的站点、补 SEO 字段、批量改标签。**默认只读**，要它动手得显式勾选权限。
- **排期**：文章日期写成未来时间就是定时发布，「日历」页能看这个月的节奏。

## 三个最容易困惑的点

**「为什么服务器预览还是旧的？」** 服务器读的是 `dist/`，所以要先生成。
勾上「保存后自动生成」就不用想这件事。

**「草稿到底会不会发出去？」** 不会。`draft = true` 的文章不进 `dist/`，
列表里带「草稿」徽标。日期在未来的也一样不进（除非你在设置里打开「立即发布未来日期」）。

**「删掉的文章能找回来吗？」** 不能，没有回收站——删的是磁盘上的源文件。
这也是推荐把站点文件夹放进 Git 的主要理由。
