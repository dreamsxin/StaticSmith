# 界面评审：按用户走一遍（2026-09-08）

这一份不是规范，是一次**评审记录**：假设六类用户各自走一遍界面，记下他们会做什么、
界面给了什么、卡在哪。规范在 [界面设计](ui-design.md) 与 [界面布局与交互约定](ui.md)，
这里只负责发现问题并指出它属于哪一类。

标注约定：凡是没在代码里核实过的，写明「未核实」——评审最容易变质的地方就是
把推测写成结论。

## 一、刚装好的写作者（零基础，目标：发一篇）

路径是通的：起始页「新建站点」选空目录 → 编辑区空态给出三步（写第一篇 / 生成一次 /
发布出去）→ 侧栏出现文章 → `Ctrl+S`。

卡点三处：

- **第一屏就是源码。** 编辑器里是正文原文，顶上还有 `+++ … +++` 那段 TOML。
  属性面板能用表单填同一份东西，但要先点工具条上的「属性」。产品定位说不必懂
  Markdown，界面的第一印象却相反。
- **右边预览取不到图片与 CSS**（`srcdoc` 沙盒没有文件访问权）。新用户的第一反应是
  「我的图没插上」，而解决办法在「工具 → 启动本地预览服务器」，且要先生成过。
- **第三步只是跳到发布页。** 到了那里要在 Git 与 FTP/SFTP 之间做一次技术决策并填凭据。
  三步引导在这一步就交棒了，没有第三条更轻的路（例如「导出一个 zip」）。

判断：「装好 → 写完」已经顺；「写完 → 线上」还是一道技术台阶。

## 二、从 Hugo 搬过来的老用户（懂 front matter，站点 300 篇）

- 导入向导扎实：强制先扫后导、列清单、目标已存在就跳过不覆盖、YAML→TOML、
  转不了的字段写成注释留在文件里。
- 批量整理够用：桌面端四种批量带干跑，CLI 也有 `staticsmith batch`，脚本化路径不断。
- **缺口是跨文件查找替换。** 换域名、统一某个写法，现在只能让 AI Agent 去改，
  或者出去用别的工具。侧栏能「找到哪几篇」，不能「替换」。
- 300 篇的渲染性能**未核实**：侧栏看着是全量 `v-for`，没有虚拟滚动的痕迹。
- 一窗口一站点，多站点并行是明确未做。

判断：迁移与整理能靠界面独立走通，唯一硬缺口是替换。

## 三、接手别人站点的运营（不懂技术，负责日更与 SEO）

- 「接手」这条路对得上：打开站点 → 体检三项 → 日历看节奏 → 侧栏「只看 → 待补 SEO」
  筛出来批改。体检每条能跳回原文。
- **栏目页的身份不一致**（真实撞到过）：`content/posts/index.md`（标题「文章归档」）
  在侧栏里长得跟文章一模一样，日历里没有（`CalendarPanel.vue` 显式跳过 `is_index`），
  「没写日期」清单也不列它。不懂 `index.md` 是什么的人只会得出「界面漏了一篇」。
- 栏目改名默认保留旧地址（可勾选），这一条保护得对。
- **不可逆动作缺兜底**：删除没有回收站，只有就地确认。而「把站点文件夹放进 Git」
  这句建议只写在教程里，界面从没说过。

判断：日常动作齐全；风险在不可逆操作，困惑在「栏目页算不算一篇」。

## 四、主题作者 / 前端

- 外观页是差异化优势：主布局 → 共享组件 → 页面模板的继承树摆在眼前，
  改一处立刻告诉你影响多少页面。
- **编辑体验是短板**：模板编辑器是纯文本 + 高亮层，没有变量补全，也没有「这个模板
  手里有哪些变量」的就地参考——那张表在 [统一模板](templates.md) 里。结构信息都在
  这一页了，上下文却不在。
- **改样式的回路最长**：`srcdoc` 预览没有 CSS，调样式基本必须开本地服务器，
  而服务器读 `dist/`，于是每次都要先生成。
- 主题包只声明 name/version/author/description，不声明依赖哪些变量或最低版本，
  装错主题要等生成时报错。

判断：结构可见性一流，编辑与预览回路是弱项。

## 五、键盘 / 读屏用户

已经补齐的：命令面板 `aria-modal` + 候选项 Tab 循环 + `aria-activedescendant`、
浮层与菜单关闭后归还焦点、菜单标题上能用方向键、就地删除确认默认聚焦「取消」、
展开式表单自动聚焦。

仍然缺的是**主结构的键盘模型**：标签栏没有 `tablist` 语义、不能用方向键切页；
三栏之间的 Tab 序没系统核过；分栏拖拽条只有鼠标能拖；月历格子不能用方向键走。

判断：浮层与菜单达标了，主界面那些「二维结构」还没被当成键盘可达的东西设计。

## 六、多站点的自由职业者

- 一窗口一站点。换站点会连带停掉预览服务器与 MCP 端点（设计如此，已写文档）。
  最近列表 5 个够用。
- 凭据按 `git:<remote>` / `ftp:<用户>@<主机>` 存进系统钥匙串——多个站点发到同一台
  主机同一账号时会共用同一条凭据。**未核实**冲突时的实际行为。

判断：串行工作没问题，多站点是明确的未做项。

## 反复出现的问题（按该修的顺序）

1. **「一篇」的定义在各视图不一致。** 栏目页在侧栏是条目、在日历不存在；产物页
   （标签页 / 分页）在侧栏另开一组；草稿与定时在不同地方用不同说法。一号与三号
   都撞上了。这不是某个面板的 bug，是模型没有在界面上统一表达。
   *（更正：「草稿与定时用不同说法」不成立——逐处 grep 过，两者措辞本来一致。
   真正分叉的是产物类型的名字：「生成」页说「标签页 / 分页页」，侧栏说「标签 / 分页」。
   这一条已修：名字收进 `src/labels.ts`，两处共用 `outputKindLabel()`。
   栏目页徽标也已补。余下的是产品问题——产物页该不该留在内容侧栏里。）*
2. **预览回路挂在「生成」上。** 一号看不到图片、四号看不到 CSS，同一个原因：
   内存预览在 `srcdoc` 沙盒里，取不到文件。
   *（更正：评审时写的「启动服务器藏在工具菜单里，与预览栏隔了两层」不准确——
   预览栏顶上一直就有「启动本地服务器」按钮，工具菜单里那一项是同一个动作的第二个入口。
   真正会绊人的是另一件事：服务器读 `dist/`，从没生成过的时候点启动只换来白屏。
   这一条已修：启动前若从未生成过就先生成一次，并在通知里说明做了什么。）*
   剩下的选择仍在：要么让内存预览能取到资源，要么承认「看完整效果=开服务器」并把这条
   写进首次引导。
   *（后续：选了前者。内存预览现在把本地样式表与图片**嵌进 HTML**
   （`staticsmith_core::preview`）：`<link>` 变 `<style>`，图片与字体变 data URL，
   CSS 里的 `url()` 一并处理。预算是单个 2 MB、一页 8 MB，超出的原样留着并回传处数，
   预览栏底部写明「还有几处没嵌进来」。脚本与外链资源仍不加载——
   「与线上完全一致」仍然只有服务器模式能保证，但「看不到图」这件事没了。）*
3. **源码优先 vs 面向写作者。** 这条要产品决策而不是工程决策：要不要给正文一个
   不暴露 `+++` 的输入模式。不做也行，但那就得承认目标用户是「愿意看源码的人」，
   并把定位文案改齐。
4. **缺跨文件替换**（二号与四号都要）。
   *（已做：「编辑 → 跨文件替换…」与 `staticsmith replace`，判断在
   `staticsmith_core::replace`。只改正文、纯文本不支持正则、必须先看干跑结果。
   仍缺的是**单篇内**的查找替换——那是另一件事，见 ui-design 第九节。）*
5. **主结构的键盘模型**（五号）。
   *（已做：标签栏是 `tablist`（方向键切页、roving tabindex），分隔条是
   `separator`（方向键 16px / Shift 64px / Home-End 到两端、`aria-valuenow`），
   月历是 `grid`（方向键走格子、PageUp-PageDown 翻月、回车进条目、Esc 退回），
   三栏 Tab 序核过：DOM 序即视线序，全项目无正数 `tabindex`。）*

前两条是结构性的、会持续制造误解；三是定位问题；四五是清晰的工程任务。
逐项修掉之后，把结论回写进 [界面设计](ui-design.md) 的规范与欠账两节，
这一份评审记录不改写为「已修」——它记录的是某一天的现场。
