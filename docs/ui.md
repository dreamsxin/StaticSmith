# 界面布局与交互约定

产品文档给的定位是「可视化的自由，工业级的静态生成」：既要像编辑器一样直接，
又不能把「全站会被怎样改动」藏起来。这份文档记录由此推出的布局与交互规则，
新增界面照着做，不必每次重新拍板。

菜单栏的分组理由、与标签页的分工、三条操作流程，以及「为什么不做 Ribbon」这类取舍，
写在 [界面设计：菜单与操作流程](ui-design.md)。那份文档的第六节是完整的视觉与交互规范
（分类学 / 刻度 / 状态矩阵 / 焦点与浮层 / 反馈与等待 / 空态 / 快捷键作用域 / 色彩令牌 /
动效），末尾 6.13 是加控件前逐条勾的清单，第九节记着「规范已定、代码未到」的欠账。
这里只记落地后的规则。


## 五层结构

```
┌ 菜单栏：站点 编辑 插入 视图 工具 帮助 ──────────────────────┐  ← 我能做什么（命令）
├ 标识行：站点名 · 路径 · 正在编辑 posts/x.md ● ─ 面板 生成 关闭 ┤  ← 在哪个站点 / 哪篇
├ 标签栏：写[内容 日历] 外观[外观] 上线[体检 生成 发布] 站点[设置]  当前页说明 ┤  ← 看什么
├ 工作区（内容页为三栏：列表 | 编辑 | 预览）─────────────────┤  ← 具体工作
└ 状态栏：进度 · 未保存 · 预览地址 · 待生成 N / M ───────────┘  ← 全站当前状态

（第六条横向条是条件出现的：磁盘上的内容或模板被外部改动时，
 标签栏下方插一行「检测到外部修改 [刷新组件树]」，改完即消失。）
```

- **菜单只放动词，标签只放名词。** 命令去菜单找（`src/commands.ts` 是唯一来源，
  菜单栏与命令面板共用），视图去标签切。「生成」在两处都有：菜单里执行，标签里看报告。
- **标签栏的分组名与标签必须一眼分清**：分组名 `0.7rem / --fg-muted / 不可点`，
  标签 `0.8rem / --fg / 500`，组内间距 `0.125rem`（2px）、组间 `0.625rem`（10px）+ 竖线。
  判别规则与状态矩阵见 [界面设计](ui-design.md) 第六节——相邻的不同类元素，
  必须在「字号 / 色彩 / 间距」里差至少两项。
- **当前页说明并入标签栏右侧**，不单独占一行：横向条每加一条，三栏工作区就窄一圈。
  窄窗口下先截断说明，不挤走标签。
- **正在编辑哪一份写在标识行**：显示 `Ctrl+S` 这一下会存谁（外观页看模板时是模板，
  其余是文章）。切到别的标签页后编辑器不在，状态栏的「● 未保存」不说明是谁没保存；
  而状态栏那一处取文章与模板的并集，两边同时挂着改动时不会漏。
- **页面跳转不进菜单**：标签栏是正规入口，搜索式跳转归命令面板（`Ctrl+P` 的「页面」组）。
  「视图」菜单只管窗格显隐——Word 的视图菜单同样不重复选项卡。
- **「插入」只放真正插到光标处的东西**。新建栏目属于「编辑」，导入内容属于「站点」；
  把跳转伪装成插入，点了看不出效果。
- 一屏只有一个主色实心按钮（标识行的「生成」，或当前面板的主动作）。其余动作保持轻量描边。
- 「切换视图」用下划线式标签页，「执行动作」用按钮——两者不能长得一样。
- 菜单里不可用的项**置灰而不是隐藏**：隐藏会让人以为功能不存在。
- 影响范围永远显示在状态栏与编辑器标题栏（`待生成 N / M`），级联更新是核心卖点，不能只在点了生成之后才知道。
- 状态栏只报告状态，不放动作。「待生成 N / M」排在左侧视线起点并用正文色，
  预览地址这类环境信息才靠右。
- **窄窗口自动收窗格**：< 1200px 收预览栏、< 900px 再收列表栏（三栏固定占用 720px，
  1024 宽只剩约 250px 给编辑器）。在「视图」菜单里手动动过的那一栏不再自动收放——
  窗口一变就改掉人的选择，比不响应式更烦人。



## 界面模式（布局预设）

定位是明确的：**正文就是源码**，目标用户愿意看 `+++` 与 Markdown，界面不在上面盖一层
平行的富文本模型。但「愿意看源码」不等于「每一刻都要看见全部面板」——写长文时属性面板
与预览是干扰，调模板时预览是主角，改一批 front matter 时属性面板才是主角。
与其替每个人猜一套默认，不如像 VS Code 那样把布局做成能一键切换的预设（「视图」菜单）：

- **标准**：列表 + 编辑器 + 预览，属性面板与工具条都在。窗格随窗口宽度自动收放
- **专注写作**：只留编辑器与工具条，收起列表、预览与属性面板，宽度全给正文
- **源码**：列表 + 编辑器，收起预览、属性面板与工具条——front matter 直接在 `+++` 里改，
  格式走快捷键

三条自我约束（`src/ui.ts` 的 `modes` 是唯一定义）：

- **模式是预设，不是约束**：切过去之后每个窗格仍可单独开关，模式不会把它扳回来。
  「模式锁死布局」会让人以为界面坏了
- **只改布局，不改能力**：任何模式下菜单、快捷键、命令面板都是全的。藏功能等于让人以为
  「这个模式不能做那件事」
- **标准模式把窗格交给窗口宽度**，另两种是用户的明确选择，因此接管显隐、不再自动收放——
  否则刚收起预览栏、一拉宽窗口它又自己冒出来

当前模式显示在状态栏右侧（只读标注，切换走「视图」菜单——状态栏只报告状态，不放动作）。
模式与两个编辑器开关（属性面板、工具条）记在本机 localStorage：这是「这台机器上这个人
怎么用」，不属于站点。

## 标签页为什么分组

七个平铺的标签（内容 / 布局管理器 / 日历 / 生成 / SEO / 发布 / 设置）看不出彼此的关系：
新用户不知道从哪开始，也不知道「生成」和「发布」是两步还是一步。所以按**做一件事的先后**
分四组，组名小而淡，只负责说明「这几个是一伙的」：

- **写**：内容（写文章、管栏目）、日历（发布节奏）
- **外观**：外观（布局与组件的继承关系、主题包的打包与装入）
- **上线**：体检（SEO / 死链 / 媒体）、生成（渲染出 `dist/`）、发布（把 `dist/` 送出去）
- **站点**：设置（`staticsmith.toml` 的表单，加一次性的内容导入）

两处改名是有意的：「布局管理器」→**外观**（它管的不只是布局，主题包也在这里）、
「SEO」→**体检**（那一页早就包含死链与媒体资源，只写 SEO 会让人以为另有入口）。

标签下面固定一行**当前页说明**：标签只有两个字，用途与关系写在这里，
鼠标悬停标签也能看到同一句。这比给每个标签配图标更直接——图标解决不了「它是什么」。

设置页同理再分一层：站点信息 / 构建 / 媒体 / 分类维度 / 导航菜单 / 发布 / 导入内容，
一次只显示一段，每段一句话说明。之前它是一张从站点标题滚到导航菜单的长表单，
找一项要滚半屏，也看不出哪些字段是一伙的。「保存设置」跟着分段一起显示并注明
「保存的是整份 staticsmith.toml，不只当前这一段」——分段是视图，不是文件边界。


## 面板与色层

- chrome（工具条、标题行、状态栏、标签页）用 `--bg-subtle`；内容区用 `--bg`。
- 成组信息用卡片：`1px` 边框 + `10px` 圆角 + `0.9rem 1rem` 内边距（`.card` 与各面板复用同一套值）。
- 面板容器底色下沉、卡片提亮，靠色层而不是粗边框分区。
- **颜色只从令牌取**，CSS 里不写字面色值。深色模式跟随系统（`prefers-color-scheme` +
  `color-scheme: light dark`），不做手动开关，所以新增令牌必须同时给亮 / 深两套值。
  令牌清单与对比度要求见 [界面设计](ui-design.md) 6.11。
- 界面几乎没有动效（只有拖拽分隔条的 0.15s 颜色过渡），展开与关闭一律硬切。
  这是取舍不是遗漏，理由见 6.12——别去「补齐」。


## 侧栏（内容列表）

「视图」菜单可以整栏关掉（列表栏 / 预览栏各一个勾选项，类比 Word 的导航窗格）。
关掉是把它从网格里去掉，而不是把宽度设成 0——宽度会被 `useSplit` 持久化并在下次启动
夹回最小值，用宽度表达显隐迟早打架。

结构固定为「标题行 → 搜索 → 分组列表 → 空态」：

- **标题行**：`内容` + 计数（过滤时显示 `匹配 / 全部`）+ 主色「新建」。
  新建入口有文字标签，不用光秃秃的 `＋`。
- **栏目页要标出来**：`posts/index.md` 这类栏目列表页在这份清单里长得跟文章一样，
  但日历不收它、「没写日期」清单也不列它（它不是某天发出去的一篇，是那个栏目的门面）。
  不标的话，用户只会得出「界面漏了一篇」——这是实际撞到过的。徽标用虚线描边 + 弱化色，
  与「草稿」「定时」这类**会变的状态**区分：它是只读标注。
- **跨面板露面的名字只有一份定义**：产物类型的显示名在 `src/labels.ts` 的
  `outputKindLabel()`，「生成」页的产物清单与这里的「站点页面（生成）」共用。
  此前两处各写一遍——那边叫「标签页 / 分页页」，这边叫「标签 / 分页」，
  同一批文件两个名字。侧栏这边还写死了三元表达式，站点地图与订阅源都会被标成「分页」。
  一律带「页」字：单说「标签」会和文章的 `tags` 字段混，那是概念，这是生成出来的页面。
- **搜索**：输入框内嵌放大镜与清除按钮，`Ctrl/Cmd+F` 聚焦、`Esc` 清空。
  搜索框绝不兼任「新建的名称输入框」——两者相邻且都无标识时会被认错，这是实际踩过的坑。
  **一个输入框，两档结果**：上面的分组列表是「标题或路径里有这个词」（本地即时过滤），
  下面的「正文里提到」是问 Rust 侧要的全文命中（正文是渲染后的 HTML，前端手里没有），
  每条给一段保留原文大小写的片段。已经在上面出现过的文章不重复列。
  两个字符起才去搜、250ms 防抖：单字符命中等于把整站列一遍，每敲一下发一次 IPC
  会把大站点拖住。判断与 MCP 的 `search_content` 共用一份实现——
  「Agent 说有、我在界面里搜不到」是最难解释的一类不一致。
- **筛选**：搜索框下面一行下拉，写成「只看 [全部内容（41）]」。选项文字把作用写全
  ——「草稿（还没发布）」「待生成（改过还没生成）」「待补 SEO（缺描述等）」
  「定时（日期未到，暂不上线）」，各自带数量，为空的那类置灰不可选。
  曾经是五个药丸按钮：在 260px 宽的侧栏里折两三行，而「草稿 / 待生成」这种两字标签
  也说不清作用。正在筛选时下拉框描边变色——否则「列表怎么少了一半」会被当成 bug。
  体检面板能说「12 篇缺描述」，但补的时候还是要回到列表里找——筛选把结论接回工作列表。
  选了非「全部」时隐藏「站点页面（生成）」组：那组不是内容，不参与内容筛选。
- **新建**：展开为带标题「新建内容」的表单，标题自动聚焦，栏目给出站内已有栏目候选，
  按钮写明后果（「创建草稿」），旁边配「取消」。
- **跨文件替换**（「编辑 → 跨文件替换…」）：与新建共用侧栏这块地方，一次只展开一个。
  查找、替换为、忽略大小写、范围（全站／只改选中的 N 篇，后者要先开「多选」）。
  **必须先「预览…」**：干跑列出哪几篇、共几处、每处前后对照，确认按钮上写着
  「替换这 N 处」——正文替换没有撤销栈。改动任一条件就作废那份干跑结果，
  避免「看的是上一次的预览、改的是这一次的输入」。
  表单里写明只改正文：front matter 字段不动，那些用批量动作或属性面板改。
  逐行对照用 `del` / `ins` 语义标签，读屏能念出「删除／插入」，颜色只是第二重提示。
- **条目**：标题 + 状态徽标（未保存 `●` / 草稿 / 定时 / 待重新生成 `●` / `SEO`，
  后者按最严重的那条问题着色，悬停给出全部问题），`title` 属性给出源路径。
  悬停显形一个「⋯」，与**在这一行上右键**打开同一份菜单：打开编辑、在预览里打开、
  发布 / 设为草稿、复制源文件路径、删除。原先这里是个「×」（只能删），
  现在一个图标换来全部动作。删除仍走就地确认——菜单项只把这一行切进确认态，不直接删。
- **多选与批量**：头部「多选」进入选择态才出现勾选框——平时不占标题宽度，
  也避免误点把批量动作作用到看不见的条目上。动作条紧挨筛选而不是浮层：
  加/去标签、发布/设为草稿、移动到栏目（默认保留旧地址）、删除。
  「全选当前」只选已按搜索与筛选过滤后可见的条目——所见即所选。
  **搬动与删除先干跑**：列出「哪几篇会怎么变、旧地址是什么、哪几篇不动及原因」，
  搬动还会把**站内其它文章里指向这几篇的链接**改到新地址，干跑里单独标黄说明
  「另会改哪几篇、共几处」——这一步写的是用户没勾的文件，不说清楚就是背着人改东西。
  不会动的行压暗，确认后才落盘；可逆的动作（标签、草稿）不加这一步。
  每次动作后清空选择，并把「改了几篇、跳过几篇及原因」报出来；没有撤销栈，
  理由见 [站点运营手册](operations.md)。
- **栏目**：分组头就是栏目本身。缺索引页时挂「缺列表页」徽标（那种栏目地址是 404）；
  悬停显形「信息」与「⋯」两个按钮，「⋯」与**在分组头上右键**打开同一份菜单
  （在此栏目新建文章、栏目信息、改名、删除空栏目）。「信息」就地编辑栏目标题、简介与排序
  （都写进索引页的 front matter，缺索引页时保存前会先说明「会顺手建一张 index.md」）；
  改名默认勾选「保留旧地址」——整理结构不该顺手打断所有外部链接。
  栏目头（名字、篇数、信息 / 改名 / 删除）是独立组件 `SectionHeader.vue`：
  它与筛选、多选、搜索完全解耦，抽出来才测得动。分组容器 `.page-list__group`
  与下面的文章列表留在 `PageList` 里——全局样式有
  `.page-list__group h3 .page-list__icon { opacity: 0 }` 这类后代选择器（hover 才显形），
  根节点跑出那层容器，按钮就会一直亮着。
  **改名先干跑再问一句**（`preview_rename_section`）：会搬几个文件、给几篇补旧地址、
  另会把哪几篇里的几处站内链接改到新地址（标黄，因为那几篇是用户没有点名的文件）。
  三条改地址的路里它一次动得最多（整棵子树），却是最后补上这一步的。删除只对空栏目生效，
  里面还有文章时菜单项直接置灰并写明原因，点也点不动。分组顺序跟索引页的 `weight` 走
  （小的在前，都不写就按路径），与站点上 `sections` 列出的顺序一致。
  空栏目也会列出来，否则「新建栏目」之后它会当场消失。
- **组内顺序就是网站上的顺序**（`grouping.ts` 的 `readingOrder`：weight 升序 → 日期降序
  → 标题）。这里曾经直接用后端给的数组顺序，而那是**源文件名字母序**——于是侧栏看着像
  文件夹而不像目录：`a.md` 永远在 `b.md` 前面，哪怕网站上是倒过来的。这套比较器是
  Rust 侧 `content::reading_order` 的孪生实现，两边各有测试钉住同样的例子。
- **「上移一位 / 下移一位」在文章的右键菜单里**（`page.up` / `page.down`），已经在头 / 尾时
  置灰。界面上没有「排序权重」这种数字：读者看到的只有先后，数字是实现细节。
  第一次挪动会把整栏的当前顺序固化成位次（因此可能改写这一栏的每一篇），通知里说清
  「把这一栏 N 篇的顺序固化下来（改写 M 篇）」——否则「我只挪了一下，怎么 30 个文件都变了」
  会像个 bug。能不能挪与真的挪共用 `moved()`，免得出现「菜单能点、点了没反应」。
  判断比的是**整栏**，不是列表上看到的那几行：筛选或搜索时列表只剩几行，而顺序是整栏的事。
- 固化过顺序之后**新建的文章（weight 0）出现在最前面**。这是有意的：新写的东西该看得见，
  而且界面与网站是同一套顺序，挪一次就固化进去了。
- **危险动作**：删除入口悬停或键盘聚焦才显形，点一次变成「删除 / 取消」的就地确认，
  不用原生 `confirm`（在 WebView 里抢焦点且样式割裂）。

## 日历（发布节奏）

定时发布让文章能排队上线，但「这个月发了几篇、下周排了什么」原先只能自己数日期。
这一页是**纯呈现**，不新增任何判断：「这篇会不会进产物」由 Rust 侧算好，
随 `PageSummary.scheduled` 一起送来，界面只按日期分格。

- 月历以周一开头，跨月的格子压暗但仍显示条目——月初月末的稿子常常就在那几格。
- 条目按状态区分：已发布是实线左边框，草稿与定时是虚线且压暗（都还不在线上）。
  点条目直接跳到内容页编辑。
- **改期在列表里做，不在格子里做**：七列的格子放不下一个日期输入框。「接下来」每行有
  「改期…」，「没写日期」每行有「补日期…」，就地展开一个 `<input type="date">`。
  它走的仍是「打开 → 改 front matter → 保存」这条现成路径，没有新增后端动作——
  排期改的就是文章的 `date`，与属性面板改的是同一处，不该有第二种写法。
  副作用是那篇会被打开，这是好事：用户看得见到底改了哪一篇。
  当前文章有未保存改动时不动手，直接说明原因（否则打开时的拦截会让这一步卡在半路）。
- 「距上次发布 N 天」比「本月几篇」更能说明节奏断没断，所以放在统计的前面。
- **没写日期**的文章单独列一块，并写明它们「一律被当成已到时间」——
  这些文章根本不出现在日历里，不点出来就等于藏了一批稿子。
- 站点开着「立即发布未来日期的文章」时给出提示：那种设置下日历只是记录，
  不是排期，改设置的入口一句话说清。

## 设置页的导航菜单与导入向导

**页内布局**：左边一列竖排分段导航，右边一列「段标题 + 一句说明 + 表单 + 保存条」。
三条理由：

- 八段横排在窄一点的窗口会折成两行，白占一条纵向空间；竖排还能一眼看完全部分段。
- 分段名只出现一次（导航里选中的那条 + 右列标题），面板内不再各写一个 `<h3>` 重复它。
- 保存条 `sticky` 在右列底部。「构建」那一段有九个输入框加四个勾选，
  按钮跟着内容滚走的话，填到一半时主动作已经不在视野里。

导航的选中态用**左边框 + 底色**，不是实心药丸：填充是动作的语言，这里是导航（6.4）。
窄于 60rem 时整页回到单列，导航横排在上面，选中态改用底边框（与标签栏一致）。
表单列限宽 44rem——输入框拉到整个宽屏那么长，眼睛要从标签走很远才走到值。

**「保存设置」显示与否**由分段表里的 `config` 字段决定，不写成
`section !== 'import' && section !== 'ai'`：每加一个会话级分段（导入、AI 接入这类做完
即生效的）都要回来补一个 `!==`，漏一个就会出现「点了保存但这一段没什么可存」。

**「源码」分段**：直接编辑 `staticsmith.toml`。定位是「正文与配置都是源码」，
那配置就不该只有表单一条路——表单认不出的键、写在配置里的注释、给别的工具看的段，
都得有地方改。三条约定：

- **逐字写回**，不格式化、不重排键。写盘前先解析并校验（Rust 侧 `SiteConfig::parse`
  + `validate`），解析不了就不落盘：一份读不出来的配置写进去，下一次打开站点连设置页
  都进不去
- 它有**自己的**保存按钮，不吃公共保存条：公共那颗写的是表单折算出的配置，
  会盖掉这里手写的文本。两颗按钮做两件事，就该长在两处，面板里也把这句说出来
- 表单保存本身也不再抹掉注释（`merge_into` 保序改写），所以两条路可以共存；
  唯一例外是数组表 `[[taxonomies]]` / `[[menu]]` 内部的注释，见
  [配置说明](configuration.md#设置页保存会保留你写的注释)


**导航菜单**是一张有序列表：名称 + 地址 + 「新窗口打开」，配「上移 / 下移 / 移除」。
界面不暴露 `weight`——让人填数字来排序是本末倒置；保存时按行序写成 `1、2、3…`，
手改配置的人看到的是同一个顺序。菜单为空时提示「模板会用自己写死的那几个链接」，
而不是显示成一张坏掉的空表。分类维度不在这里登记，模板自己遍历 `taxonomies`。

**导入向导**：从别的站点搬内容不是「选个目录点确定」——一次迁移动几十上百篇，
看错目录就是一堆半成品文件躺在 `content/` 里。所以界面强制两步：

- **先扫后导**：「扫描（不写文件）」只读，列出每篇「来源 → 会写到哪」，
  目标已存在的压暗并挂「已存在」徽标（导入绝不覆盖），转不动的字段直接把警告
  列在那一行下面。确认清单没问题，才点「导入 N 篇」。
- 清单可能上百条，容器给高度上限（`.settings__import-list`），不把整页撑开。
- 导完自动重扫一次：已经进来的会变成「已存在」，还剩什么一眼可见。
- 判断全在 Rust 侧（与 `staticsmith import` 同一套 `scan` / `import`），
  界面不自己推导「这篇能不能导」，否则预览与结果早晚会不一致。

**AI 接入**（设置页最后一段）：开一个只监听 127.0.0.1 的 MCP 端点，让支持 MCP 的助手
读写这个站点。它与「导入内容」同类——是**会话级动作**，不写进 `staticsmith.toml`，
所以这一段不显示「保存设置」那一条。三条设计约束：

- **默认只读**，「改内容与模板」「执行发布」两个开关要显式勾。不勾发布时那一项置灰
  （发布的是产物，而产物来自内容与模板；只给发布等于给一个改不了东西却能推旧产物上线的
  权限，说不通）。文案写清后果：删掉的文章没有回收站，发上线的稿子撤不回来。
- **权限只在启动时决定**，改权限就是重启这个端点；界面显示的权限从**正在跑的服务端**
  读回来，不由前端记着——记着就会出现「勾了写入、其实只读」。
- 开着时给出端点地址与「复制端点地址」，并说明 Agent 改的是磁盘：改完之后顶部会出现
  「检测到磁盘上被外部修改」，点一下刷新。不假装两边实时同步。

**主题包**（在「外观」页，不在设置页——它换的是那一页列出的模板与主题资源）
同样「先扫后装」：选包之后立刻扫描并列出会写的每个文件，
已存在的挂「已存在」徽标；不勾「覆盖」时那些行压暗，按钮上的数字也跟着变
（写的是「装入 N 个文件」而不是「确定」，点之前就知道后果）。被拒绝的条目
（越界路径、`templates/` 与 `theme/` 之外的位置）连原因一起列出来，不静默丢弃。
打包一侧只有名字/版本/作者/说明四个输入 + 一个「另存为」对话框，
名字留空就用站点标题；文案明说「包里不含 content/ 与 static/」——
那是最容易被误解成「会不会把我的文章打包出去」的地方。

## 命令面板（Ctrl+P）

标签页解决「我在做哪件事」，但站点一大，「这篇文章在哪个栏目」「体检在哪个标签页里」
又成了负担。命令面板把导航与动作合并成一个输入框：

- 一处入口同时搜索**命令、文章、模板、产物页面**；空关键词时每组只给前几条，
  先回答「能做什么」而不是铺一屏文件名
- 匹配只做子串（标题与路径都算），不做模糊打分——排序玄学会让人怀疑「是不是漏了」
- `↑` `↓` 选择、`Enter` 执行、`Esc` 关闭；点空白处也关
- 快捷键是 `Ctrl+P` 而非 `Ctrl+K`：后者在编辑器里是「插入链接」
- 执行后自动切到该动作所属的标签页，不需要用户先切页再操作
- 浮层只留给「暂时盖住一切、只回答一个问题」的场合（命令面板、新建站点、回退内容、
  消息、大纲、站内链接）。其他确认交互仍用就地元素
- 焦点：打开即聚焦输入框，`Tab` / `Shift+Tab` 在候选项之间走（焦点始终留在输入框里，
  这就是这个浮层的 focus trap），`Esc` 关闭并把焦点还给打开它的那个元素

### 所有浮层的共同约定

命令面板之外还有五层浮层（「新建站点」「回退内容」「消息」「大纲」「站内链接」）。
六者共用这几条：

- 写了 `aria-modal="true"` 就必须真的圈住焦点。命令面板靠「Tab 改成移动高亮」达成，
  其余几层用 `src/focus.ts` 的 `trapTab()`：Tab 走到尽头回卷，焦点在浮层外时收回来。
  不给背景加 `inert` / `aria-hidden`——浮层渲染在主结构同一棵树里，标掉外层会连它一起标掉。
- 点空白关闭绑 `click.self`，不绑 `pointerdown.self`：按下即关会在「从遮罩起手拖选文字」
  时误关一层浮层。
- 取消与关闭按钮**不跟随** `store.busy`。忙态是全局单锁（一次保存触发的后台生成也会
  置上它），让取消跟着变灰的结果是「后台在忙时浮层关不掉」。变灰只用于会写东西的按钮。


## 快捷键

快捷键分三层，作用域不同，写在括号里；层级规则见 [界面设计](ui-design.md) 6.10。

- `Ctrl+P`：命令面板（全局。语义是「打开并聚焦」，与标识行按钮、视图菜单一致；关闭用 `Esc`）
- `Ctrl+Enter` / `Ctrl+Shift+Enter`：增量生成 / 完整重建（全局）
- `Ctrl+S`：保存**当前正在编辑的那一份**（全局）。外观页看着模板时存模板，其余存文章；
  落点是 `commands.ts` 的 `saveTarget()`，菜单项标题跟着变，不必猜按下去存了谁
- `Ctrl+Shift+F`：找**哪一篇**（全局）。切到「内容」页、必要时打开被关掉的列表栏，
  再聚焦侧栏搜索框；`Esc` 清空
- `Ctrl+F`：找**这一篇里的第几处**（编辑器内，控件级）。展开查找／替换那一行，
  有选区时拿选区当查找词。焦点不在编辑器里时 `Ctrl+F` 仍然等于「找文章」——
  这个键在两种上下文里有两种含义，是刻意的：它总是「在你正看着的东西里找」
- 编辑器内：`Ctrl+B` 加粗、`Ctrl+I` 斜体、`Ctrl+K` 插入链接（控件级）
- `Ctrl+Shift+O`：大纲（编辑器内，控件级）。各家编辑器的「转到符号」都是这个键；
  不带 Shift 的 `Ctrl+O` 刻意放过，那是系统与将来的「打开」
- `Ctrl+Shift+K`：站内链接（编辑器内，控件级）。与 `Ctrl+K`「插链接」同一个字母，
  多按一个 Shift 就是「链到站内的一篇」——这层关系比另找一个字母好记
- 起始页上全局快捷键都不生效（还没有站点，命令无处施加）

同一个键只注册一层：textarea 上的事件会继续冒泡到 window，两层都留着 `Ctrl+S` 会存两次。
编辑器内的 `Ctrl+F` 是唯一一处刻意 `stopPropagation()` 的地方——不拦住，
window 上那个「找文章」会紧接着把焦点抢到侧栏。

全局层的按键**不该抢走正在打字的人的输入**：焦点在 `textarea` / `input` 里时，
控件与浏览器的原生行为优先。


## 键盘走位（主结构）

快捷键之外，主界面那些**二维结构**也要能只用键盘走。原则：一片结构只占一个 Tab
停靠点，进去之后用方向键（roving tabindex）。否则「跳过日历」要按四十多下 Tab。

- **标签栏**是 `role="tablist"`：`←` `→` 换视图、`Home` / `End` 到两端。
  焦点即选中——切视图是纯导航、代价很低，再要求按一次回车只是多一步。
  分组容器是 `presentation`：ARIA 规定 tablist 的子节点除 `tab` 之外只能是无语义包装，
  组名（写／外观／上线／站点）本来就是给眼睛的装饰。工作区是对应的 `tabpanel`
- **三栏的 Tab 序**就是 DOM 序，也就是视线序：列表 → 分隔条 → 编辑器 → 分隔条 → 预览。
  没有一处 `tabindex` 正数（正数会把元素抽到所有自然停靠点之前，从此没人能推理出顺序）
- **分隔条**是 `role="separator"` + `tabindex=0`，方向键 16px、`Shift` 64px、
  `Home` / `End` 到两端，`aria-valuenow` 让读屏念得出当前宽度。以前它只有鼠标能拖：
  键盘用户不但改不了分栏，连它存在都感知不到
- **月历**是 `role="grid"`：方向键走格子（`↑` `↓` 是上下周）、`Home` / `End` 到本周两端、
  `PageUp` / `PageDown` 翻月并停在同一天。回车进入格子里的条目，`Esc` 退回格子；
  条目自己不占 Tab 停靠点。空格子也能聚焦——「走到 12 号看看那天有什么」是日历的基本用法，
  而以前只有「有文章的那几颗按钮」在键盘世界里存在
- 可聚焦的非按钮元素都要有自己的焦点态：分隔条整条变主色（6px 宽画不了描边），
  月历格子用内描边（格子间只有 1px 缝，`outline` 会被邻格盖掉一半）



## 编辑器

- **属性面板**里的「地址（slug）」栏改的不只是字段：改完会自动把旧地址补进 `aliases`、
  把站内指向这一篇的链接改到新地址（`change_slug`，见 [站点运营手册](operations.md) 第五节）。
  **先就地问一句再落盘**（`preview_slug`）：「地址将从 A 改为 B，旧地址会保留，
  另会改写 N 篇里的 M 处站内链接」——这一步要写用户没有点名的文件，与搬动、删除同一条约定。
  索引页那一栏置灰并说明「栏目索引页的地址就是栏目名，请用侧栏的栏目改名」——
  置灰不隐藏。这一篇有未保存改动时会拦下来让人先存盘：改地址要写 front matter，
  缓冲区随后一保存就把结果盖掉。取消会把输入框读回磁盘上的值：留着没生效的文本
  会让人以为改成了。
- **三处改地址的干跑都分两类报**（改 slug、搬动、栏目改名）：能自动改好的引用报
  「另会改写 N 篇里的 M 处」，改不到的**相对链接**（`../a/`）单独报
  「另有 N 篇里的 M 处相对链接指向它，需要手工改」。分开说是因为两者对用户的要求不同：
  前者是知会，后者是待办。相对地址按引用方所在目录解析，而改地址改的是被引用方，
  所以自动改写只能处理根绝对地址。
- **大纲**（`Ctrl+Shift+O`，或「编辑 → 大纲…」，工具条右侧也有）：这一篇的目录，
  点一条或按回车把光标送到那一行。标题从**源文**抽（`src/manuscript.ts` 的
  `parseOutline`），不经过渲染，所以边写边有；front matter 与围栏代码块里的
  `# 注释` 不会混进来。层级用缩进表达，另标一个 `H3` 之类的小字给缩进兜底。
  做成浮层而不是常驻侧栏：编辑器已经三栏，再挤一栏正文就没宽度了，
  而目录是「用一下就走」的东西，与命令面板同类。
- **字数与预计阅读时长**在页脚：中文按字、西文按词，front matter 与代码块不计入
  （读者不会读它们），按每分钟 300 字估算。长文写着写着就没了长度感——
  纸质书有厚度和页码，这里本来只有一个滚动条。
  规则只有一份（`countWords`），不许工具条与页脚各算一套。
- **站内链接**（`Ctrl+Shift+K`，或「插入 → 站内链接…」，工具条也有）：挑一篇，
  地址由站点数据给出。以前只有 `Ctrl+K`，插出来是 `[文字](https://)`——链到站内
  就得自己记地址或切去列表看一眼，而手打的地址正是死链的来源，且要等「体检」页才发现。
  有选区就拿选区当链接文字，否则用对方的标题。草稿标出来但不禁用（草稿不进产物，
  链过去会是死链；但「先写互链、后补那一篇」是常见顺序）。筛选规则与命令面板同款：
  只做子串、不做打分，候选上限 50 条并在顶到上限时说明。
  拼接规则在 `src/crossref.ts`：Markdown 站点给 `[文字](地址)`、HTML 站点给 `<a>`
  （正文格式是 HTML 时插 Markdown 会渲染成一行带方括号的纯文本），
  链接文字里的 `[` `]` 转义、地址含空格或括号时用 `<>` 包住。
- **查找 / 替换这一行**（`Ctrl+F`，或「编辑 → 在这一篇里查找 / 替换…」）：
  上一处／下一处、替换这处、全部替换、忽略大小写，带「第 3 / 12 处」计数，
  有选区时拿选区当查找词。不做浮层——查找条要和正文同时看得见，
  浮层正好会盖住命中的那一行。替换只改缓冲区，落盘仍走 `Ctrl+S`，
  通知里明说「还没保存」。规则与跨文件替换一致：纯文本、不做正则、不重叠计数。
- **源文着色**：`textarea` 文字透明、只留光标，背后垫一层同字体同行高的高亮镜像
  （`src/source-highlight.ts`）。标题、代码、链接、front matter 各有其色，
  但改的仍是纯文本——不引入富文本模型，也就不会出现「界面样式与源文不一致」。
  两层的字体、字号、行高、内边距、换行规则必须逐项一致，差一点就错位。
- 着色器自己写，不引 CodeMirror/Prism：编辑器只需要「看清结构」，
  为折叠与补全塞进几百 KB 依赖不划算，而且高亮规则要与站点支持的 Markdown 子集一致。
- 超过 20 万字符不着色：整篇重扫的开销开始能被察觉，而收益接近零。
- **着色规则跟着站点的正文格式走**（`build.source_format`，见
  [配置说明](configuration.md)）：Markdown 站点按标题、行内标记、围栏代码着色；
  HTML 站点按标签、属性名、引号里的值、注释着色。HTML 站点里满屏标签，
  按 Markdown 着色等于把它们全当普通文字。两种格式共用
  `src/source-highlight.ts` 一份实现，由参数分派——front matter 那段
  （`+++` 包起来的 TOML）两种格式完全相同，拆成两个文件就要复制它，
  而它已经踩过「文件开头的 `+++` 才算 front matter」这个坑。
  HTML 那条路是逐字符扫**原文**再逐段转义：先转义的话 `<` 变成 `&lt;`，
  任何「找标签」的正则都会失效。
- **模板着色**同一套机制，规则换成 HTML + Tera（`src/template-highlight.ts`）：
  先把 `{% %}` / `{{ }}` / `{# #}` 从 HTML 里挑出来，再分标签名、属性名、属性值。
  模板里最容易看错的就是「这段是 HTML 还是 Tera」。

## 发布

- **「一键发布…」先干跑再问一句**（`plan_deploy`）：确认区列出目标、将上传几个文件与
  总字节、跳过几个、前 8 个文件名，以及这次干跑的代价与限制（FTP 已连服务器但只读、
  Git 会写 `dist/.git` 的暂存区但不推送、远端多余文件不会被删除）。
  就地确认而不是浮层：清单要和目标、覆盖规则同时看得见。
  发布是唯一影响**线上**的动作——别的动作改错了还能在本地改回来，这个改错了是
  别人看到的页面变了，所以它必须和搬动、删除、改地址一样有这一步。
- 没有要传的文件时确认按钮置灰（那次发布什么也不会发生），干跑失败时不进确认态。
- 取消不写任何东西，因此**不跟随** `store.busy`（同浮层的约定）。
- **发布与干跑期间都能停**：「一键发布…」换成「停止」，点过之后变「正在停止…」并置灰
  （连点几次而界面毫无反应比停不下来更糟）。旁边一句话说清停在哪儿——干跑那步
  「只读远端，停下来什么也不会改，但也不会给出清单」，上传那步「停止在当前这个文件
  传完之后生效，不会留下半个文件，已经传上去的那些下次发布会跳过」。
  这个按钮跟的是 `store.deployPhase`（`'plan' | 'upload' | null`）而不是 `store.busy`——
  挂在忙态上，保存文件时也会冒出一个「停止」；而两个阶段停下来的后果不同，
  用同一句话说会有一句是错的。停止点与各通道的差别见 `docs/deploy.md`。
- **「被停止的」和「发完了」必须一眼分得出来**：结果区在 `cancelled` 时先说一句
  「上次发布是被停止的，不是发完了」。两者的上传数可能都是 12，一个是全部、一个是一半。

- **文章行的徽标有优先级**（`PageRow.vue`）：未保存 > 草稿 / 定时，三者共用同一个位置。
  未保存是唯一会丢东西的状态，被草稿盖住的代价最大。栏目页与「待生成」各占自己的位置。
  删除只能从右键菜单（或行上的「⋯」）进入，进去之后仍要再点一次「删除」；
  确认态里「⋯」让位给「删除 / 取消」两颗，而取消不受忙态影响。
  行内的样子归组件，「哪一行在确认删除、菜单里放什么」归 `PageList`——菜单项要调
  `actions` 也要读筛选态，搬进组件只是把耦合换个地方藏。

- **历史占用常驻在「回退内容」里**（`snapshot_usage`）：快照是唯一随使用无声长大的东西

  ——每次不可逆操作留一份，换一张大图就多存一份那张图的完整副本。看不到就永远不会想起
  清理，直到某天发现项目目录多了几个 G。超过 200 MB 才追加一句清理办法（`git gc`）并
  说清代价（删掉的历史无法找回）：常驻信息不该长期摆成警告。

- **回退快照也先给你看一眼**（`SnapshotDialog.vue` 的第二步）：选中一条即干跑，

  列出会换回旧版、删掉、找回哪几个文件（最多 8 行，其余给数量），三类各几个先说一句汇总。
  回退动的是整个内容目录、模板与 `staticsmith.toml`，此前只有一句「这之后的改动会被撤销」——
  它是最后一个没有清单的写操作。`changes` 为空时确认按钮置灰（那一下点了也没有任何结果），
  干跑失败不进确认态（同发布面板）。

- **读不出来的源文件在列表里有自己的位置**（`BrokenList.vue`，摆在栏目分组之前）：

  front matter 手改坏了的那几篇没有 `PageSummary`（解析不了就没有标题、地址、栏目），
  但必须点得到——只弹一条「有 2 篇读不出来」的通知，等于让用户自己去文件管理器里找。
  点开就是纯文本编辑（`actions.openBroken`，仍走未保存确认那道拦阻），编辑区顶上有横幅
  说明原因（`brokenReason`，由项目摘要推导，修好保存后自己消失）。
  这几篇不渲染预览：渲染必然失败，而那句报错用户刚在列表里看过一遍。

- **跨文件替换**（`ReplacePanel.vue`）与「多选」共用一个「范围」概念：勾了几篇时能

  只改那几篇，所以选中集合由 `PageList` 传进来。**改了任一条件（查找词、替换词、
  忽略大小写、范围）就把上一份干跑结果作废**——否则屏幕上留着旧清单，
  而「替换这 N 处」按的是新条件，用户以为自己确认的是看到的那份。
  没预览过不给按替换；一处都没命中时说明白并置灰。

- **侧栏顶部三块可展开的表单（新建内容、新建栏目、跨文件替换）共用一个状态**
  （`PageList` 里的 `panel`），互斥因此是结构上的事实。以前是三个布尔量各自开关，
  而「点『新建』时收起『新建栏目』」那一笔恰好漏了：两张表单会叠在一起，
  还同时绑同一份 `#known-sections` datalist。两张新建表单本身在 `CreatePanel.vue` 里。
- 表单里的**取消不清输入**（误点一下不该把刚写的标题丢掉），**建成之后才清**；
  「栏目」一格记住上一次填的，只有栏目头的「在此栏目新建文章…」才覆盖它——
  连着往同一个栏目里写几篇是常态。
- 已经展开着又被要求新建一次（菜单里的「新建文章…」、Ctrl+N）时，
  至少把光标送回第一格：按下去界面毫无反应，看起来像坏了。


## 反馈



- 所有失败一律弹通知（`store.run` 统一兜底），不允许只写进状态而界面无反应。
- **成功也要有可见结果**：界面内容变了、弹了通知、或某个数字变了，三者至少有一个。
  三者都没有的动作用户会再点一次。
- 通知加在**命令**那一层，不加在被复用的动作里：`actions.refresh()` 被保存、批量、导入、
  生成共用，通知写在它里面就会变成「每次保存弹一条」。菜单的「重新读取磁盘」因此走
  `commands.ts` 的 `refreshFromDisk()`，体检则用 `announce` 参数区分主动点与顺带重跑。
- 通知：错误停 8s、成功与提示停 3.5s，都可手动关闭，右下角纵向堆叠，同屏最多 3 条。
  批量结果**一条讲完**（「已处理 5 篇；跳过 2 篇，都是「目标已存在」」），不逐条弹。
  这一行由 `src/skips.ts` 生成，与命令行、MCP 用的是同一句话（Rust 侧 `staticsmith_core::skips`）：
  同一个动作在三个入口说法不同，用户就得在三处各学一遍。

- **一行装不下的部分进「详情」**（`notify` 的第三个参数 → 消息中心里的折叠块）。
  截断没问题，被截掉的部分没有落点才是问题：「另有 3 篇同样没改成」「5 条生成警告：第一条 等」
  读完之后用户无处可查，只能自己去 grep 全站。现在有四处这样报：批量跳过的每一篇、
  改地址时没改成的引用、生成警告、导入警告。只有一条时不摆折叠块——那条已经整句显示了。
- **跳过的原因按种类说全**（`src/skips.ts`）：只报第一条原因加「另有 N 篇」的话，
  五篇里有两种原因时第二种从没露过面，而用户会按看到的那一条去排查——查错方向比不给信息更费时间。
  所以一行里给「3 篇「A」、1 篇「B」」，一种原因时说「都是「A」」，一篇时直接报是哪一篇。
- **一篇都没动时不报成功**：绿勾配「已处理 0 篇」等于说做完了，没人会去查为什么。
  那种情况说「没有需要改的，什么都没动」（提示级）。一篇都没做成而有跳过的，是错误级。

- **通知消失之后还查得到**：状态栏右侧的「消息」（也在「视图」菜单与命令面板里）留最近
  100 条，带时间与程度。气泡是瞬时出口，而最需要事后再读一遍的恰恰是错误——手改
  `staticsmith.toml` 存盘失败时，Rust 侧那条带行列号的 TOML 报错飘走之后就无处可查。
  未读数只在有新消息时出现，打开面板即归零（记「看过的最大 id」而不是布尔标记，
  这样面板开着又来新消息也算得对）。
- 通知的**抢读策略按程度分**：错误用 `role="alert"`（assertive，打断读屏器当前朗读——
  操作失败要立刻知道），成功与提示用 `role="status"`（polite）。整个容器统一 polite 的话，
  最该被听到的那条反而排在最后。状态栏的进度也是 polite：它连续刷新，抢读会一直打断用户。

- 进度文字是过程量，操作结束必须清空，让状态栏回到「就绪」；停在旧进度上看起来像还在跑。
  实现在 `store.ts`：忙态计数归零时同时清空 `progress`，两件事一处做完，不会漏。
- 忙态用计数器而不是布尔：嵌套执行时布尔会让按钮在一次操作里闪几次。复合动作
  （保存、生成、批量、打开站点）在入口用 `busySpan()` 先占一格，中途每步之间不会归零。
- 失败一律弹通知；**留在界面上**的那一份目前只有起始页的 alert（打不开站点时那句话
  必须留着）。主界面里需要用户处置的错误就地显示在出问题的那一块，不做全局常驻错误条。
- 破坏性或不可逆的操作先就地确认；可逆的直接做完再报结果。
- 需要前置条件的动作自己补齐条件（例如点产物预览会自动拉起本地服务器），而不是先弹一句「请先启动服务器」，
  但要说出正在补什么（「正在启动本地预览服务器…」），否则用户只看到一个不知在等什么的忙态。

细节与起因见 [界面设计](ui-design.md) 6.8；空态的分档规则见 6.9。
